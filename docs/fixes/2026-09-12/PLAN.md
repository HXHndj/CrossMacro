# 分阶段修复与交付计划

授权：用户要求分阶段完成上一轮审查问题，每轮修改后 Git 提交，并验证最终交付物可用和稳定。

基线：`11766a21f4e0c24707991132976f9ec69b66db01`，开发分支 `codex/phased-stability-performance`。保留原有未跟踪 `.zcode/`，不纳入本次提交。

| 轮次 | 范围 | 最低验证 |
| --- | --- | --- |
| 0 | 固化审查证据与本计划 | 工作树范围检查 |
| 1 | 任务 mutation 回滚、脚本空白解析、异步剪切 | 保存失败/取消、混合空白、等待期间选区变更回归 |
| 2 | Windows 输入分发/停止、native wait、GetMessage、屏幕轮询 | 使用替身测试超时/异常/取消，不向真实桌面注入输入 |
| 3 | 设置/Profile/文本扩展持久化与切换 | 故障注入、路径/缓存一致性、原有 profile 回归 |
| 4 | 编辑器投影/撤销/加载/预览 | 行对象/集合通知、撤销语义、受控分配计数、预览取消 |
| 5 | 键盘交互、本地化、busy反馈、列表视口及官网 | UI 契约与行为测试、官网构建（可用时） |
| 交付 | 提交后的整体验证与 Windows 包 | 相关完整测试组、Release 构建/发布、隔离 CLI smoke、记录 hash 与限制 |

每轮只暂存对应源文件/测试/阶段说明，由主审核验后提交。多 agent 的写入目录和文件范围互斥；构建/测试只由一个执行者串行进行，禁止对同一脚本重复启动。测试使用临时目录，交付 smoke 只用隔离配置和 dry-run，避免触发用户现有自动化。

不把审查候选当作必须改造的事实：ArrayPool 清零、生命周期半启动契约、Precision 标签等先核实。实现保持格式兼容和既有语义；不得以减少数据/隐藏错误/删除原测试获得通过。

验证应保留命令、退出码、TRX/控制台日志，并采样本任务进程树 RSS 与 Private Bytes。先小批量，达到预算保存证据并退出，不重启同一高内存实现。原先符号链接测试的 Windows 特权限制单独报告，不假称全部通过。

各阶段状态、实际提交与最终验收在阶段报告和 DELIVERY.md 中记录；本计划不是已完成声明。
